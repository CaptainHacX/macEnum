# macEnum Audit Tool

`macEnum` is a comprehensive, read-only macOS local enumeration and privilege escalation auditing script for authorized security assessments, red team engagements, pentests, and internal audits.

It is written specifically for macOS internals and avoids Linux-only assumptions such as `/proc`, `/etc/shadow`, `systemctl`, `getcap`, `dpkg`, or `yum`.

## Safety Notice

This tool is **100% read-only**. It does not modify, delete, install, disable, exploit, or attack anything. It only uses inspection-style commands such as read, list, show, get, and status checks.

Use this script only on systems you own or are explicitly authorized to assess.

## Quick Start

```bash
cd /path/to/macEnum
chmod +x macEnum_v4.sh
./macEnum_v4.sh
```

Run a deeper scan:

```bash
./macEnum_v4.sh -t
```

Save output to a report file:

```bash
./macEnum_v4.sh -t -q -o report.txt
```

Export findings to JSON and HTML:

```bash
./macEnum_v4.sh -t -j findings.json -H report.html
```

Run only selected sections:

```bash
./macEnum_v4.sh -s privileges,launch,security,defensive
```

Skip privacy-sensitive sections:

```bash
./macEnum_v4.sh -x sensitive,browsers
```

## Usage

```bash
./macEnum_v4.sh [options]
```

## Options


| Option    | Description                                                                                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-t`      | Thorough mode. Enables slower/deeper checks such as credential filename sweeps, dylib dependency scans, Wi-Fi profile metadata, clipboard inspection, and keychain item metadata inventory. |
| `-q`      | Quiet mode. Disables ANSI colors. Useful when saving output to a file or piping output.                                                                                                     |
| `-F`      | Findings-only mode. Suppresses informational output and prints only findings plus the final summary.                                                                                        |
| `-T`      | Shows section timing. Useful for identifying slow checks.                                                                                                                                   |
| `-o FILE` | Saves a full copy of terminal output to `FILE`.                                                                                                                                             |
| `-j FILE` | Exports findings as machine-readable JSON.                                                                                                                                                  |
| `-H FILE` | Exports findings as a styled HTML report.                                                                                                                                                   |
| `-s LIST` | Runs only the comma-separated section keys in `LIST`.                                                                                                                                       |
| `-x LIST` | Runs everything except the comma-separated section keys in `LIST`.                                                                                                                          |
| `-h`      | Shows built-in help.                                                                                                                                                                        |

## Major Feature Areas

### System Security Configuration

- System Integrity Protection status
- Authenticated root / sealed system volume status
- Gatekeeper assessment status
- FileVault status
- Application Firewall status
- NVRAM boot arguments
- Remote Login and remote access service checks
- XProtect and MRT presence/version indicators

### Privilege Escalation Assessment

- Current sudo capabilities
- Non-interactive sudo checks
- Sudoers policy risk parsing
- SUID and SGID binary discovery
- Writable PATH directory and binary checks
- Writable sensitive directories
- Writable files under `/Library` and `/usr/local`
- PAM configuration and writable PAM modules
- Authorization database weakening checks
- Privileged helper tools and XPC root helper review
- Dylib injection and weak load path checks
- Writable root-owned application bundles

### Launchd and Persistence

- LaunchDaemon and LaunchAgent enumeration
- Launchd plist ownership and mode checks
- Launchd target path, symlink, ACL, and writable-parent checks
- StartupItems
- Login items
- Cron and periodic jobs
- `at` jobs
- emond rules
- Login/logout hooks
- SecurityAgent and authorization plugins
- Shell init persistence
- PATH injection files
- Spotlight, QuickLook, ScreenSaver, Audio, and contextual plugin bundles

### Credential and Sensitive Data Discovery

- SSH private keys and SSH config
- `known_hosts` lateral movement hints
- Auto-login `/etc/kcpassword`
- VNC/ARD password file presence
- AWS, GCP, Azure, Kubernetes, Docker, OCI, and other cloud CLI artifacts
- AWS SSO and AWS STS cache metadata
- GCP ADC and token database indicators
- Azure MSAL/token cache indicators
- GitHub, npm, PyPI, RubyGems, Terraform, and `.netrc` token stores
- Shell history and filtered environment variables
- Keychain metadata inventory without secret dumping
- Wi-Fi profile names without password retrieval
- TCC-gated personal data store paths

### Browser and Application Artifacts

- Safari profile artifacts
- Chromium-based browser profiles
- Firefox profiles
- Browser extension directories
- Saved login databases and cookie/history databases
- Installed applications and package receipts
- Homebrew, MAS, pip, gem, and npm package inventory

### Defensive Stack Detection

- EDR, AV, DLP, MDM, and telemetry product detection
- Exact path, launchd label, system extension, package receipt, and process matching
- Endpoint Security and network system extension visibility
- Third-party kernel extension detection
- Full Disk Access checks for detected security tools
- PPPC and system-extension management profile indicators
- Security product installed-but-not-running findings
- Explicitly disabled security launchd labels
- Problematic system extension states
- VPN/compliance-agent tamper-resistance (e.g. GlobalProtect running as a user-level LaunchAgent without `KeepAlive`, which lets a standard non-admin user disable enforcement with no auto-restart)

### Privilege Escalation Chains and CVE Exposure

- Writable `/etc/synthetic.conf`, `sudoers.d`, local directory-service (dslocal) store, periodic/newsyslog/PAM/CUPS paths, and launchd directories
- macOS ACL-granted write access beyond POSIX permissions
- Dangerous group memberships (`admin`, `_developer`, `_lpadmin`, kernel/process-memory groups)
- Live sudo / cached-credential checks
- Writable Full-Disk-Access-holding apps and writable TCC databases (TCC privilege-escalation chains)
- macOS local-privesc / SIP-bypass / TCC-bypass CVE exposure mapped by OS build version
- Sparkle auto-update framework version checks

### Secret and Credential Content Scanning

- High-confidence hardcoded token/key pattern matching (cloud provider keys, VCS/CI tokens, SaaS API keys, private key blocks) with pruned, size-bounded, depth-bounded filesystem scanning
- Secret-like assignments in `.env`/`.tfvars`/`.netrc`/config-style files
- High-entropy key=value pairs in thorough mode
- All matched secret values are masked in output, never printed in full

### Security Hardening and Weak Permissions

- macOS end-of-support version checks
- Login window, guest account, and auto-login policy
- Screen-lock and password-after-sleep policy
- Automatic security update configuration
- Sharing/remote-access service exposure and `sshd` hardening
- Non-loopback listening services and network-stack hardening (IP forwarding, promiscuous mode)
- `/etc/hosts` hijack detection
- Permissions on SSH keys, cloud credentials, and other credential files/directories
- `authorized_keys` review and other-user data exposure

### Exploitation Surface and Lateral Movement

- Cached Kerberos tickets and SSH `known_hosts`/config lateral-movement targets
- Saved/recent network servers (SMB/AFP/VNC/FTP) as pivot targets
- Sensitive environment variables exposed in readable process listings
- Defense-evasion and tamper indicators (disabled authenticated-root, stale XProtect definitions, disabled security launchd services)
- Process-injection surface and Mach-O hardening audit of running root binaries
- Incident-response triage timeline (recently modified binaries/accounts)

### Containers and Developer Tooling

- Docker presence, containers, images, and writable Docker socket
- Podman, Colima, Lima, and nerdctl detection
- Kubernetes context listing
- VM/hypervisor indicators
- Xcode and Command Line Tools
- Language runtimes
- Compilers and interpreters
- Writable global package directories

## Output and Findings

The script prints human-readable sections to the terminal. Findings are emitted with severity labels:

- `CRIT`
- `VULN`
- `!`
- `low`

Findings are also tagged with MITRE ATT&CK technique IDs where applicable.

At the end of the run, the script prints:

- Overall host risk label
- Risk score
- Count of findings by severity
- Grouped finding summary

## Privacy and Prompt-Safety Notes

- Wi-Fi password retrieval is intentionally not performed to avoid Keychain/admin prompts.
- Keychain checks inventory metadata only and do not dump secrets.
- Some checks need Full Disk Access to read TCC-protected files.
- Browser databases, Messages, Notes, Mail, and some TCC databases may be inaccessible without Full Disk Access.
- Run as a normal user for realistic post-exploitation-style visibility.
- Run as root only when you specifically need root-only evidence, such as local password hash visibility or protected system artifacts.

## Troubleshooting

### The script is slow in thorough mode

Use section filtering:

```bash
./macEnum_v4.sh -t -s security,defensive
```

Or show timings:

```bash
./macEnum_v4.sh -t -T
```

### Output has ANSI color codes

Use quiet mode:

```bash
./macEnum_v4.sh -q -o report.txt
```

### Some checks show empty output

This is expected when:

- A native macOS command is unavailable on that OS version
- The current user does not have permission
- Full Disk Access is required
- Optional tools such as `brew`, `mas`, `docker`, or `kubectl` are not installed

### I only want findings

Use findings-only mode:

```bash
./macEnum_v4.sh -F
```
